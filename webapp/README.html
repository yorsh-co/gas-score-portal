# 🌐 Documentação do WebApp Frontend **Sistema: Publicação de Notas v3** --- ## 📌 Visão Geral O WebApp Frontend do **Publicação de Notas** é a interface pública do sistema, responsável por: * Permitir que usuários consultem suas notas * Exibir resultados processados na planilha * Consumir dados do backend (Apps Script WebApp) * Oferecer uma experiência simples, rápida e responsiva O frontend é servido através de um deployment do tipo **WEB_APP** do Google Apps Script. --- # 🏗 Arquitetura do Frontend O frontend funciona como: ``` Usuário → Navegador → WebApp (Apps Script) → Planilha → Dados Processados ``` Ele: * Recebe requisições HTTP (`doGet`) * Interpreta rotas via parâmetro `?route=` * Renderiza HTML dinamicamente * Consulta dados na aba 💯 Notas * Exibe resultados filtrados --- # 🚀 Publicação A publicação é feita diretamente pelo menu da planilha: ``` ⚙️ Configurações → 📲 Publicar ou atualizar o WebApp ``` O sistema: 1. Cria uma nova versão do script 2. Cria ou atualiza o deployment 3. Salva automaticamente: * `deploymentId` * `versionNumber` * `webappUrl` --- # 🔗 Estrutura de URL URL base: ``` https://script.google.com/macros/s/{DEPLOYMENT_ID}/exec ``` Se configurado: ``` ?route=nomeDaRota ``` Exemplo: ``` https://.../exec?route=/users/scores ``` A rota inicial pode ser definida em: ``` ⚙️ Config → appsScript.entryRoute ``` --- # 🧭 Sistema de Rotas O frontend utiliza roteamento baseado em query string: ```javascript ?route= ``` Permite: * Separar páginas internas * Criar áreas administrativas * Criar diferentes layouts Exemplo de possíveis rotas: | Rota | Finalidade | | ----- | --------------------- | | users | Consulta individual | --- # 🖥 Estrutura de Renderização O WebApp utiliza: * `HtmlService` * Templates HTML * Injeção de dados via script-side Fluxo típico: 1. `doGet(e)` recebe parâmetros 2. Determina rota 3. Consulta dados na planilha 4. Injeta dados no template 5. Retorna HTML final --- # 📊 Consumo de Dados Os dados vêm da aba: ``` 💯 Notas ``` Estrutura: * Linha 1 → URLs dos Forms * Linha 2 → Timestamp da útima sincronização * Linha 3 → Pontuação máxima * Linha 4 → Título do forms * Linha 5+ → Participantes O frontend pode: * Buscar por e-mail * Listar notas por formulário * Exibir médias --- # 🔐 Segurança O nível de acesso do WebApp é definido no deployment: * Executar como: proprietário do script * Quem pode acessar: * Qualquer pessoa com o link ⚠️ Recomenda-se validar entradas do usuário para evitar: * Consultas inválidas * Exposição de dados indevidos --- # 🎨 Personalização Visual Configurações disponíveis na aba ⚙️ Config: | Campo | Uso | | ----------- | ---------------------------------- | | webappTitle | Título exibido na aba do navegador | | faviconUrl | Ícone do site | # 📱 Responsividade * Layout flexível (Flexbox ou Grid) * Fonte legível * Botões grandes para uso mobile * Feedback visual em carregamentos O WebApp roda em: * Desktop * Mobile * Tablets --- # ⚡ Performance Boas práticas adotadas: * Dados já normalizados na planilha * Sincronização pré-processada no backend * Sem cálculos pesados no frontend * Uso mínimo de requisições adicionais --- # 🔄 Atualizações Sempre que o frontend for alterado: 1. Salvar alterações 2. Atualizar WebApp pelo menu O sistema atualiza automaticamente o `versionNumber`. --- # 🧪 Testes Recomendações: * Testar com: * Usuário com notas * Usuário sem notas * E-mail inválido * Testar rotas inexistentes * Testar múltiplos formulários --- # 📦 Integração com Backend O frontend depende de: * `ScoresSheet` * `Config` * Dados sincronizados previamente Ele **não processa respostas diretamente do Forms** — apenas lê dados consolidados. --- # 📌 Resumo O WebApp Frontend: * É a camada pública do sistema * Consome dados já consolidados * É publicado automaticamente * É modular e roteável * Pode evoluir independentemente da sincronização --- # 📄 Licença O cliente recebe direitos comerciais de uso sobre o sistema entregue.
